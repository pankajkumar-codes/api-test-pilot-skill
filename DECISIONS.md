# DECISIONS

Format: date — decision — reason.

- 2026-11-12 — Skill format: Agent Skills (folder with SKILL.md) — portable across Claude and other marketplaces.
- 2026-11-12 — Accessibility testing excluded from v1 — not meaningful for APIs; revisit as separate UI skill.
- 2026-11-12 — Safety gate required for load/stress/spike/soak/chaos/fuzz — marketplace trust and abuse prevention.

- 2026-11-12 — GraphQL included in v1, built in Phase 2 — runs over HTTP/JSON so most modules are reusable; needs its own intake and security checks.
- 2026-11-12 — gRPC deferred to v2 — needs a separate toolchain (proto, grpcurl/ghz) and load tooling.
- 2026-11-12 — Hosted service not a goal — a skill runs in the user's environment; hosting adds infra, billing and legal risk for load/attack testing.

- 2026-11-12 — Single repo — the skill runs in the user's environment, so no core/hosting split. Marketplace packaging (e.g. Claude Code plugin) = extra manifest files in the same repo.
- 2026-11-12 — Functional test stack: pytest + httpx/requests — readable, editable code; portable; generators emit pytest.
- 2026-11-12 — Load tool: k6 — single binary, GraphQL over HTTP, thresholds give pass/fail.
- 2026-11-12 — License: MIT — permissive and simple for an open-source skill.
- 2026-11-12 — Display name and GitHub repo name: `api-test-pilot`; skill folder/identifier stays `api-testing` — branded repo, stable skill path and `name:` in SKILL.md.
- 2026-11-12 — Chaos scope: plan generation only in v1; executable fault injection deferred to v2 — safety and abuse risk.

- 2026-11-12 — One normalized intake JSON for all inputs (OpenAPI, Swagger 2.0, Postman, curl), documented in references/intake.md — generators in Phase 2 depend on one shape, not on the input format.
- 2026-11-12 — YAML: use PyYAML if installed, else a built-in subset reader (no anchors/aliases, errors clearly) — keeps scripts stdlib-only and offline per CLAUDE.md without breaking common specs.
- 2026-11-12 — Parsers never emit secrets: auth becomes env-var names (APITEST_<SCHEME>_TOKEN/USER/PASS/KEY), secret-looking headers and body fields are dropped or `<redacted>` — enforces the no-secrets rule at the earliest point.
- 2026-11-12 — Parsers are offline: remote URLs and external $refs are not fetched (warning instead); multi-file specs must be bundled first — safety and reproducibility.
- 2026-11-12 — Skill scripts are tested with pytest in repo-level tests/ (fixtures in tests/fixtures), not shipped inside the skill folder — keeps the installable skill small.

- 2026-11-12 — Generated suites use `requests` + a copied `apitest_runtime.py`, not a shared pip package — one stack for REST and GraphQL, nothing for users to install besides pytest/requests, and the suite stays editable and portable. (`httpx` stays an allowed alternative; revisit if users ask for async.)
- 2026-11-12 — Suite layout: `conftest.py` + `apitest_runtime.py` + `endpoints.py` (valid baseline requests) + one `test_<type>.py` per type, with case tables and `rt.*` helpers — tests stay short and readable; regenerating overwrites, edits are for the user's copy.
- 2026-11-12 — Test-type boundaries: negative = auth/ids/malformed requests, data-validation = one schema violation per case, edge = accepted boundaries and "never 5xx" inputs, contract = responses vs schema — no case is generated twice.
- 2026-11-12 — Safety gate for active probes in security/resilience/GraphQL abuse checks (`intrusive` marker): allowed only on local hosts, or non-production `APITEST_TARGET_ENV` plus `APITEST_AUTHORIZED=yes`; production blocks even local hosts; non-local targets need `APITEST_TARGET_ENV` at all — extends CLAUDE.md's gate to functional-adjacent probes without weakening it.
- 2026-11-12 — Destructive calls (DELETE on existing ids, `delete*` GraphQL mutations) need `APITEST_ALLOW_DESTRUCTIVE=yes`; integration flows delete only data they created — protects user data while keeping lifecycle coverage.
- 2026-11-12 — Existing ids come from env (`APITEST_PATH_<PARAM>`, `APITEST_GQL_<ARG>`) or spec examples; otherwise the test skips and names the variable — no guessing, no hidden state.
- 2026-11-12 — Opt-in flags for checks that are noisy by default: `APITEST_EXPECT_RATE_LIMIT`, `APITEST_ASSUME_NON_ADMIN` (BFLA), `APITEST_GQL_EXPECT_FIELD_AUTH`, `APITEST_GQL_REQUIRES_AUTH`; opt-outs for deliberate settings: `APITEST_ALLOW_INTROSPECTION`, `APITEST_ALLOW_BATCHING` — the tests cannot know the intended policy.
- 2026-11-12 — Secrets in generated output: spec examples/defaults for secret-named fields are never used (`REPLACE_ME` placeholder); the runtime redacts failures and curl repros using the same `SECRET_KEY_RE` as the parsers (injected at generation time) — one source of truth for "looks like a secret".
- 2026-11-12 — GraphQL intake reuses the REST shape (one `POST /graphql` endpoint + a `graphql` block) and the `APITEST_BEARERAUTH_TOKEN` credential; schema parsing is offline (SDL parser built in, introspection JSON accepted), never queries the endpoint — Phase 3 k6, reporting and auth work unchanged.
- 2026-11-12 — GraphQL variables carry all test input (never string-concatenated into queries); subscriptions are listed but not tested in v1 (needs WebSocket/SSE).
- 2026-11-12 — GraphQL v1 test types: smoke, positive, negative, edge, security. Contract/integration/data-validation/resilience are REST-only for now.
- 2026-11-12 — Generators and the runtime are validated by running generated suites against stdlib mock servers with seeded bugs (tests/mock_rest.py, mock_graphql.py), because eval-apis.md targets are not reachable from the build sandbox; real eval runs remain Phase 5.
- 2026-11-12 — Breaking-change detection (`spec_diff.py`) works on intake JSON, so one tool covers OpenAPI, Postman and GraphQL; it reports spec changes, not client usage.
- 2026-11-12 — Generated code never embeds spec strings raw: every id, path, name and URL is emitted through repr (or sanitized for docstrings/comments), the base URL baked into conftest must match a strict URL charset, and a hostile-spec test (REST and GraphQL) proves nothing executes — a spec is untrusted input and the generated suite runs on the user's machine.
- 2026-11-12 — Local-host auto-pass is limited to `localhost`, `127.*`, `::1` and `*.localhost`; `.local`, `.internal` and `.test` names can be real corporate hosts, so they need `APITEST_TARGET_ENV` (and `APITEST_AUTHORIZED=yes` for intrusive tests). A local address is assumed to be the user's own machine; `APITEST_TARGET_ENV=production` still overrides it.
- 2026-11-12 — `APITEST_TARGET_ENV=production` sends read-only calls only: intrusive probes and every POST/PUT/PATCH/DELETE (and GraphQL mutation) are skipped, because functional write tests would change real data.
- 2026-11-12 — Local-host check uses `ipaddress` loopback for IP literals and the literal name `localhost`/`*.localhost` only (no string prefixes: 127.0.0.1.nip.io is remote); the host must parse identically with urllib.parse and urllib3, and URLs with backslashes/whitespace or non-http(s) schemes are refused. Decimal/hex IP spellings count as remote.

- 2026-11-12 — Phase 3 k6 design: open-model `ramping-arrival-rate` (fixed request rate, VUs only capped) with per-stage `stage` tags and per-endpoint `endpoint` tags — a slow server cannot reduce the pressure, and the summary shows breaking point, spike recovery and soak degradation instead of one average. One script per profile, one shared JS template, all spec data in one JSON document read with `JSON.parse` (never string-built code); `node --check` runs at generation.
- 2026-11-12 — Load safety defaults: GET/HEAD only; POST/PUT/PATCH need `--include-writes` at generation and `APITEST_ALLOW_WRITES=yes` at run time; DELETE and GraphQL mutations never; admin endpoints opt-in; no redirects; hard caps 100 req/s, 200 VUs, 4 h, steady ramps at most 5 req/s per second (spike ramps at least 5 s), defaults far lower (5 req/s, 20-50 VUs); a breaker aborts at 50 % failures. Run-time env caps can lower, never raise. — non-functional runs must be hard to point at a service by accident.
- 2026-11-12 — Non-functional gate = Phase 2 gate, stricter in spelling: `scripts/safety_gate.py` (stdlib) and a JavaScript copy inside every k6 script, with parity tests (46 URLs x 10 environments) against each other and against the pytest runtime. Production is refused even on a local address; loopback, `*.localhost`, canonical 127.x.x.x and `::1` pass; any URL with userinfo, backslash, odd host spelling or a parser disagreement is refused. The launcher `run_k6.py` checks before k6 starts and forwards no arbitrary k6 flags (caps cannot be bypassed from the command line); scripts also check at start-up so `k6 run` directly is gated.
- 2026-11-12 — The gate variables are never set by the skill: the user exports `APITEST_TARGET_ENV` and `APITEST_AUTHORIZED=yes`; launcher and SKILL.md say so — an agent confirming its own authorization would void the gate.
- 2026-11-12 — `--quick` (stages 10x shorter, minimum 3 s) is the way to check ids, credentials and thresholds before a real run; its results are not capacity numbers. Tests use it so real-k6 runs finish in seconds.
- 2026-11-12 — k6 tests run only when a k6 binary exists (`K6_BIN` or PATH) and skip with a reason otherwise; generation, static, hostile-spec, gate and fuzz tests need no k6. Phase 3 was validated with k6 v1.3.0 (checksum-verified release binary).
- 2026-11-12 — GraphQL load: query operations only, selections without secret-looking fields, ids from `APITEST_GQL_<OP>_<ARG>` / `APITEST_GQL_<ARG>`, bearer token sent when configured; HTTP 200 + non-empty `errors` counts as a failed check (bodies are read only for GraphQL).
- 2026-11-12 — Fuzzing: built-in seeded fuzzer (`fuzz_runtime.py`, requests + stdlib) instead of wrapping Schemathesis — offline, no extra dependency, reproducible (fixed default seed), same `intrusive` gate and redaction as the rest of the suite; Schemathesis stays an optional alternative documented in references/fuzzing.md. Opt-in (`--types fuzz`, excluded from `all`), REST only (GraphQL fuzzing deferred; GraphQL security checks cover depth, alias, batching and injection). Hard caps: 500 cases per endpoint, 5000 requests per run, 20 req/s, 1 MiB payloads; findings never print response bodies.
- 2026-11-12 — Chaos stays plan-only (as decided in Phase 0): `gen_chaos_plan.py` emits Markdown with no fenced code and no commands, a gate section and an unchecked pre-flight checklist, refuses production, copies no free text from the spec (titles, summaries, descriptions), and validates dependency names — plans are read by people and AI assistants, so spec text is untrusted there too.

- 2026-11-12 — Phase 4 report = one script, `summarize_results.py`, filling `templates/report.md` through a single-pass `{{placeholder}}` substitution (values are never re-scanned; unknown placeholders are an error). Inputs are pytest JUnit XML and k6 `--summary-export` JSON only — both are what the Phase 2/3 runners already produce, so nothing in the generators changes and the report works for any pytest run. In `--summary-export`, a threshold value `true` means crossed (verified against real k6 v1.3.0).
- 2026-11-12 — Result files are untrusted input: expat is used directly (streaming, no tree) and any DOCTYPE, entity declaration or external entity is refused whatever the encoding; files must be regular files under a size cap (25 MiB XML, 10 MiB JSON) with depth, case-count and per-field caps; `system-out`/`system-err` are never read; JSON rejects NaN/Infinity and non-numbers become `n/a`. Nothing from a result file is executed, imported or fetched.
- 2026-11-12 — One redaction helper: `_common.redact_text` (exact values of secret `APITEST_*` env vars, URL userinfo, Authorization/Cookie headers, Bearer tokens, JWT and common token shapes, `curl -u`, values of secret-looking keys in JSON, key=value and query strings) built on the shared `SECRET_KEY_RE`; it runs BEFORE truncation (a cut must not leave half a secret), is linear-time (tested on pathological input) and over-redacts rather than leaks. The report also scrubs its own regenerate command (a `--title` could carry a secret).
- 2026-11-12 — Markdown output rule: untrusted text is either escaped (prose, table cells, headings: backslash-escapes, `://` and `www.` broken so nothing autolinks, control/bidi/zero-width characters removed) or placed in a fenced block whose fence is longer than any backtick run inside; commands are built from validated parts and shell-quoted, so a hostile test name is one argument.
- 2026-11-12 — Severity in the report: the `[HIGH|MEDIUM|LOW]` tag the test wrote wins (most severe tag when a test lists several, as the fuzzer does); untagged failures get a per-type default and are labelled "default for this test type" (smoke, security, fuzz HIGH; edge, resilience LOW; others MEDIUM). k6: crossed error-rate or checks threshold HIGH, latency MEDIUM, stress profile capped at MEDIUM (crossing a limit is its purpose), failed check MEDIUM. Errors (setup, collection) are "Run problems", never findings and never a pass (`INCOMPLETE` when nothing else failed).
- 2026-11-12 — Reproducible command per finding: the runtime's redacted `curl` line(s) when present plus `APITEST_BASE_URL=... python -m pytest <dir>/<file>::<test> -v` (or `scripts/run_k6.py <dir>/<profile>.js`). `--base-url` is syntax-checked only (http/https, no credentials or query); the report never classifies a host, never sets the gate variables and adds the gate note for security, fuzz, resilience and k6 findings.
- 2026-11-12 — Review fixes (PR 4): `repro:` curl lines from result files are parsed with shlex (never run), accepted only in the exact runtime shape, must target the same scheme/host/port as `--base-url` (or `APITEST_BASE_URL`; none means no curl line), and are rebuilt with shell quoting; rejected lines are dropped and the finding says so. PASS needs an executed passing test or k6 requests, otherwise the result is INCONCLUSIVE (empty and all-skipped suites are not passes). Duplicate classname+name cases count once, worst outcome wins. Overlong or scrubbed test names rerun the whole file, not an invalid node id.

- 2026-11-12 — Phase 5 eval honesty rule: results are labelled by what ran ("mock-based, real target not run", "real local server", "real target run by the person"); mocks are never presented as the real service, expected-test patterns are fixed in `evals/run_evals.py` before a variant is scored, and known gaps are recorded as gaps (`gap` field) rather than dropped from the table. The mocks and the generators come from the same authors, so mock results prove the pipeline and the checks on seeded flaws, not detection in unseen software.
- 2026-11-12 — Eval layout: `evals/` (driver, mocks, vendored upstream specs with hashes, real local FastAPI target, README with real-target commands). One flaw per run plus a clean variant, because combined flaws hide which test caught what and a clean run is the only false-positive measure. Real mode takes a base URL from the person, never guesses a target, and never sets `APITEST_TARGET_ENV` or `APITEST_AUTHORIZED` (the gate stays the user's).
- 2026-11-12 — Test-data skips, not verdicts: a 429 where another status was expected, and a create refused as a duplicate (409, or 400/422 saying "already exists"), skip with a reason. Trade-off: a target that always answers 409/429 shows skips instead of failures, which the report lists with their reasons; failing on them produced false positives on every stateful or throttled API in the evals.
- 2026-11-12 — Destructive tests run last in the generated suite, and authorization probes (BOLA/BFLA) run first among them: otherwise earlier tests consume the ids later tests use, and a probe running after the account deleted itself passes by accident.
- 2026-11-12 — Admin detection also reads the summary/description ("Only Admins", "admin only", "requires admin"); new login-enumeration check (API2) needs a known username from `APITEST_KNOWN_USERNAME` and is intrusive (two failed logins, lockout risk), so it stays behind the gate. Deferred: mass-assignment read-back (v1.1), uniquifying baseline create bodies (v1.1; duplicates are skips for now), login success-path tests with real credentials.
- 2026-11-12 — Reports warn next to write-method repro curls (POST, PUT, PATCH, DELETE change data) and say that `<redacted>` headers must be replaced with the user's own credentials before a curl line works (Phase 4 review follow-ups).

- 2026-11-12 — Phase 6 packaging: the repository root is both the Claude Code plugin and a one-plugin marketplace (`.claude-plugin/plugin.json` + `marketplace.json`, `source: "./"`), because `skills/api-testing/SKILL.md` already sits where plugins expect skills. Trade-off: an install copies the whole repository (tests, evals, docs) into the plugin cache; acceptable for 0.1.0, revisit by moving the plugin into a subfolder. Plugin and marketplace are both named `api-test-pilot` (kebab-case, not on the reserved lists); the skill name stays `api-testing`.
- 2026-11-12 — One version, three places (SKILL.md `metadata.version`, `plugin.json`, top CHANGELOG heading), enforced by `tools/validate_skill.py`; `plugin.json` sets `version`, so users get updates only when it is bumped. Nothing is tagged, released or submitted by the build: those steps are the maintainer's (docs/RELEASE.md).
- 2026-11-12 — The validator is stdlib-only and reads the small YAML subset skills use instead of requiring PyYAML; it enforces the Agent Skills spec (name rules and folder match, description 1-1024, compatibility 1-500, string-only metadata) plus two stricter rules: no angle brackets in the description (the Claude app rejects them) and every file SKILL.md names must exist. It checks that scripts compile but never runs or imports them.
- 2026-11-12 — LICENSE copyright holder is the GitHub login `pankajkumar-codes` (no holder was named anywhere in the repo); the maintainer may replace it with a legal name. No plugin icon is shipped: the directory wants a square PNG and a made-up logo would be worse than none.
- 2026-11-12 — Safety follow-up from Phase 5: the generated conftest refuses to start (`pytest_sessionstart`, `rt.preflight`, pytest usage error, exit code 4) when the target is remote and `APITEST_TARGET_ENV` is unset, before any request is sent; the old fixture-time error remains as a backstop. `--collect-only` is not blocked. Destructive ordering uses a `destructive` marker added by the generator at emission time (generated text only, never spec text) instead of `inspect.getsource`. Under pytest-xdist each worker orders its own share; documented rather than fixed.
- 2026-11-12 — A run where more than half of the tests skip prints a warning at the end of pytest and adds a bold warning to the report verdict; the verdict word is unchanged (PASS stays PASS, nothing-executed stays INCONCLUSIVE) so the existing rules are not loosened or tightened.
- 2026-11-12 — Treat `RecursionError` like "not JSON" wherever untrusted JSON is parsed or redacted (runtime repro and describe, response parsing) and report over-nested input from `intake.py` with exit 2 — Python 3.11's lower recursion limit made five fuzz tests fail; a hostile server or spec must never crash the tool or hide a finding.
- 2026-11-12 — All CLIs that read `intake.json` go through `_common.load_intake_json` and print `error: ...` with exit 2 for unreadable, binary or non-intake files — one validation path instead of a traceback per script.
- 2026-11-12 — Supported Python is 3.11, 3.12 and 3.13 (all run in CI); dependency floors stay `pytest>=8`, `requests>=2.31`, `pyyaml>=6` because the full suite passes on exactly those lowest versions. No upper bounds and no lock file: the skill ships generated source, and users' environments differ.
- 2026-11-12 — CI lint is ruff with only syntax and pyflakes rules (`ruff.toml`): it catches real errors without forcing a style rewrite. The k6 job is optional (`continue-on-error`) because it has not been proven on GitHub runners yet.
- 2026-11-12 — `run_evals.py` deletes the previous junit and report before each run, so a leftover file can never stand in for the current result; `--target all` checks for fastapi and uvicorn up front.
- 2026-11-12 — Vulnerability reports go to private GitHub security advisories (SECURITY.md); responsible-use rules live in SECURITY.md and are linked from the README.
- 2026-11-12 — Redaction fails closed: `redact()` replaces anything nested deeper than 64 levels wholesale, and a body that cannot be parsed or redacted because of the recursion limit is replaced by a fixed placeholder, never printed raw. Review found the first fix (treat `RecursionError` as "not JSON") printed the raw body, canary secret included. Canary tests run at depths 700, 1200 and 100000 on 3.11 and 3.13.
- 2026-11-12 — GitHub Actions are pinned by tag (`@v4`, `@v5`, `@v1`), not commit SHA, because the SHAs could not be verified from the build environment; the workflow says so. Pin them before the public launch.
- 2026-11-13 — Multi-API eval follow-ups. (1) Throttle lives in the runtime's single request path (`Api._request`), set by `APITEST_DELAY_MS` / `APITEST_RPS` or the pytest options of the same name (the options write the env vars in `pytest_configure`, so REST and GraphQL share one path); the slower limit wins; default is no throttle. (2) Only connect-phase failures (refused, DNS, connect timeout, proxy tunnel; not TLS or URL errors) retry GET/HEAD/OPTIONS `APITEST_RETRIES` times (default 2) and then SKIP with "target unreachable"; the terminal summary counts them. Writes are never retried. Reviewer finding: skipping every connection error hid servers that crash or hang on a bad input and made a dead target exit 0, so errors after connecting (reset, read timeout, truncated body) now FAIL for every method, smoke tests fail when the target is unreachable, and `APITEST_UNREACHABLE=fail` makes that global. Fuzz passes `transient="raise"` and classifies errors itself. Rate-limit probes skip while a throttle is set (a paced burst would report a false "never throttled"). The guessed-parameter note rides on the response, not module state. (3) The unknown-id test is generated only for id-like path parameters (name or uuid format, or a documented 404 on a single-parameter endpoint); other parameters stay at their normal value. (4) Values with no spec backing are not sent for optional parameters; required ones are flagged `guessed` in `endpoints.py` and the failure text says the value was invented. (5) Gate skips are re-located to `conftest.py` in the report so `-rs` groups them into one line; the gate logic and its message are untouched.
- 2026-11-13 — Chaos is executable, overriding the Phase 0 decision "chaos = plan generation only in v1" (the person asked for it). Why: plans alone could not tell the user whether the API recovers. How it stays safe: same single gate as load and fuzz (`safety_gate.gate_reason`, production always refused, remote needs APITEST_TARGET_ENV + APITEST_AUTHORIZED=yes); fault commands are user-supplied argv lists in a config file, never guessed, never run through a shell, run only with `--allow-hooks` and only for loopback targets, each fault has an undo that runs on error, Ctrl-C and SIGTERM; proxies bind 127.0.0.1 only and their upstream must pass the gate; hard ceilings in code (50 req/s, 120 s per fault, 60 s outage, 30 min run, 1 MiB payload, 100-request burst, 10 s latency). `gen_chaos_plan.py` stays as the planner. Trade-off: a Python proxy adds latency of its own and speaks only HTTP/1.1 without chunked request bodies; real chaos tooling (toxiproxy, tc, Chaos Mesh) remains the answer for production-like platforms.
- 2026-11-13 — Chaos results reuse the JUnit path (classname `chaos.test_chaos`, type `chaos`, rated MEDIUM by default, intrusive note) and carry a `rerun:` line that the report accepts only in the exact chaos_run.py shape, so reporting needed no new format.
- 2026-11-13 — `--dep-proxy` experiments need the API pointed at the proxy before they start, so the runner waits (`--wait-for-target-s`) and skips with a reason when no traffic passed through; it never rewrites the API's configuration.
- 2026-11-13 — `APITEST_READ_ONLY=yes` is the "public sandbox" mode: writes and every intrusive probe are skipped (central guard in `Api.send` and `raw_post`), and a remote target needs no APITEST_TARGET_ENV because nothing that changes data or probes actively is sent. It never enables anything the gate would block, and load, fuzz and chaos keep their own gate.
- 2026-11-13 — A credential parameter (`Authorization`, `X-API-Key`, `api_key`, ...) on an operation with no security declared anywhere is inferred as auth (scheme `inferred_<name>`, env var `APITEST_INFERRED_<NAME>_KEY`/`_TOKEN`) with a parser warning; an explicit `security: []` stays public and a declared scheme is never overridden.
- 2026-11-13 — Required body fields with invented values are listed in `Endpoint.guessed` as `body.<field>`; the failure text of a 4xx names them, nothing is suppressed. Create responses without an id skip the flow (with the reason) instead of failing it.
- 2026-11-13 — Review fixes on the chaos PR: the target's and probes' query strings (and URL credentials in hook arguments) are never printed or written; the report rebuilds the chaos rerun command from validated experiment names and the intake path and drops the result file's own line (untrusted); `APITEST_READ_ONLY` is enforced in pytest, k6 (write methods skipped) and `chaos_run.py` (payload and dependency-command experiments skipped); undo entries leave the list only after the command ran, signals (INT, TERM, HUP) are held during cleanup, and undo commands run in their own session.
- 2026-11-13 — Eval follow-ups: field-name hints (`email`, `status`, `url`, `port`) only replace the generic `sample-<name>` / `1` when the spec has no example, default, enum, range, format or pattern, and the value stays a guess (omitted for optional params, flagged for required ones). Integration flows are skipped for path params that are not resource ids (same `is_id_param` rule as the unknown-id test) unless the create response documents that field. `chaos_run.py` exit 4 = cut short by a signal (a separate code so a partial run is never read as a pass or as ordinary failures). A secret in the URL path is documented, not scrubbed: paths are needed to show which endpoint failed. The `destructive` marker and xdist note were already in (Phase 5).
- 2026-11-14 — Reports are HTML by default (single file, inline CSS/JS/SVG, CSP blocks external loads) with a JSON twin; no charting library is vendored. Why: the person wanted a modern report that works offline and attaches to tickets; hand-written CSS and SVG avoid a dependency, a licence notice and a CDN. Markdown stays available by extension (`-o x.md`) because the evals and chaos tests score the Markdown form.
- 2026-11-14 — Request/response per test travels in the JUnit XML as an `apitest.http` property (written from the teardown report, which is what junitxml reads), not a side file: one artifact to pass around, and the report already treats the XML as untrusted. The runtime redacts at capture (fail closed on deep or large JSON: body omitted), the report scrubs again. Cap: 3 exchanges per test, 1500 characters per body, 20 000 per property.
